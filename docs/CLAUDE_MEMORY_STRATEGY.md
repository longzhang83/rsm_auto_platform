# Claude记忆策略

这是一个系统性的策略，确保我能在未来开发中记住和应用所有学到的经验教训。

## 🧠 记忆系统架构

### 1. **即时触发机制**
关键词 → 立即检查相关文档：
- `callback` → `MEMORY_CHECKLIST.md` (函数参数匹配)
- `async` → `DEVELOPMENT_PATTERNS.md` (异步模式)
- `file` → `DEVELOPMENT_PATTERNS.md` (文件操作)
- `progress` → `TROUBLESHOOTING_GUIDE.md` (进度回调)
- `encoding`/`中文` → `TROUBLESHOOTING_GUIDE.md` (编码问题)
- `error`/`exception` → `TROUBLESHOOTING_GUIDE.md` (异常处理)

### 2. **开发流程检查点**
```
开始开发 → 阅读MEMORY_CHECKLIST.md → 编码过程 → 提交前检查
```

### 3. **代码注释提醒系统**
在关键代码位置添加🚨标记注释，直接指向文档参考

## 📋 强制检查清单

### 开发开始前（必须执行）
1. 阅读 `docs/MEMORY_CHECKLIST.md`
2. 确认当前任务类型，回顾相关模式
3. 检查是否涉及回调函数、异步操作、文件处理

### 编码过程中（持续检查）
- 每次定义回调函数：检查参数签名
- 每次调用回调函数：验证参数匹配
- 每次引入新依赖：评估必要性
- 每次文件操作：使用with语句
- 每次异步操作：控制并发，处理异常

### 代码提交前（最终验证）
- [ ] 所有回调调用都正确匹配参数
- [ ] 所有关键操作都有异常处理
- [ ] 所有文件操作都使用with语句
- [ ] 日志输出包含足够上下文
- [ ] 没有引入不必要的复杂依赖

## 🎯 核心经验总结

### 最容易犯的错误（必须警惕）
1. **函数参数不匹配** - 最常见，影响最大
2. **异常中断流程** - 导致整个批量操作失败
3. **资源泄露** - 文件未正确关闭
4. **编码问题** - 中文字符处理不当

### 最有效的解决方案
1. **严格按照函数签名调用** - 不想当然使用关键字参数
2. **异常处理不重新抛出** - 避免中断主流程
3. **使用with语句** - 自动管理资源
4. **明确指定编码** - encoding='utf-8'

## 📖 如何使用这个记忆系统

### 当遇到新问题时
1. **首先**：检查 `MEMORY_CHECKLIST.md` 中的症状描述
2. **然后**：查看 `TROUBLESHOOTING_GUIDE.md` 中的具体解决方案
3. **最后**：参考 `DEVELOPMENT_PATTERNS.md` 中的正确模式

### 当开始新功能开发时
1. **必读**：`MEMORY_CHECKLIST.md` 的开发前清单
2. **参考**：`DEVELOPMENT_PATTERNS.md` 的相关模式
3. **避免**：查看反模式，不要重复错误

### 当代码审查时
1. **检查**：所有关键点是否都有注释提醒
2. **验证**：是否遵循了最佳实践模式
3. **确认**：是否避免了已知的反模式

## 🚀 持续改进
